# Linux と Wayland のサポート

OpenPen は Linux で動作しますが、ディスプレイセッションによって左右される**条件付きサポート**です。

- **X11 / Xorg セッション** — macOS や Windows と同一の、全機能を使える体験です
  (フローティングボール、展開・折りたたみ、ドラッグによるスナップ、ピン留め、縦型バー)。
- **ネイティブ Wayland セッション** (GNOME、対象は 46 以降) — 動作はするものの**機能が限定**された体験です。フローティングボールの代わりに、固定表示のコントロールバーが常に表示されます。

これはコンポジターの制約に合わせた意図的な対応であり、未完成の移植ではありません。Wayland 上の OpenPen は、フローティングボールを備えた完全な UX ではなく、実用本位の画面アノテーションツールとして動作します。

---

## 使用中のセッションを確認する

```bash
echo "$XDG_SESSION_TYPE"   # → "x11" or "wayland"
```

全機能を使いたい場合は、**Xorg** セッションでログインしてください
(下記の[Linux で全機能を使うには](#getting-the-full-experience-on-linux)を参照)。

## 機能サポート一覧

| 機能 | X11 / Xorg | ネイティブ Wayland (GNOME) |
| --- | --- | --- |
| 描画オーバーレイ (フリーハンド / 直線 / 図形) | ✅ | ✅ |
| 線の太さ、色、ハイライトモード | ✅ | ✅ |
| フローティングボール | ✅ | ❌ (代わりに固定コントロールバー) |
| ボールのドラッグ / 端へのスナップ / ピン留め | ✅ | ❌ |
| ボールへの折りたたみ / 縦型バーレイアウト | ✅ | ❌ |
| コントロールバーの位置 | ボールに追従 | 左上に固定、常に表示 |
| コントロールバーを隠す (占有領域の解放) | ✅ | ✅ — `Ctrl + Shift + \` またはトレイ |
| キーボードショートカット | ✅ | ✅ — GNOME のみ |
| カーソル基準の操作 (カーソル位置への呼び出し) | ✅ | ❌ |
| マルチモニター | ✅ | ⚠️ バーはアクティブな画面に表示され、画面をまたぐドラッグは不可 |

## Wayland の制限事項の詳細

ネイティブ Wayland セッションでは、次の制限があります。

- **フローティングボールがありません。** コントロールバーは固定サイズのウィンドウで、左上隅に固定され、常に表示されます。ドラッグ、ボールへの折りたたみ、ピン留め、縦型レイアウトへの切り替えはできません。
- **バーが占有領域を塞ぎます。** Wayland ではバーのウィンドウをクリックスルーにできないため、バーが覆っている領域は、その下にあるアプリから操作できません。この領域が必要なときは、**`Ctrl + Shift + \`** (既定) またはトレイメニューでバーを隠し、同じ方法で再表示してください。
- **ショートカットは GNOME 専用です。** OpenPen は、切り替え操作 (描画モードの切り替え、バーの非表示) を GNOME のカスタムキーバインドとして登録します。既定は `Ctrl + Shift + A` (描画モード) と `Ctrl + Shift + \` (バーの非表示) です。KDE などの他の Wayland コンポジターにはまだ対応していません。
- **カーソル基準の機能はありません。** Wayland はグローバルなポインター位置をアプリケーションに公開しないため、グローバルなカーソル位置に依存する操作 (カーソル位置への呼び出しなど) は利用できません。
- **描画キャンバスは必要に応じて作成されます。** 描画オーバーレイは描画モードに入るときに作成され、描画モードを終了するときに破棄されます。完了したストロークは保持されますが、まれに、描画モードを終了した時点でまだ描画中 (ポインターを離していない) のストロークが失われることがあります。これを避けるには、ストロークを完了して (ポインターを離して) から、描画モードをオフにしてください。
- **マルチモニター。** コントロールバーはアクティブな画面に表示され、画面をまたいでドラッグすることはできません。

## Linux で全機能を使うには {#getting-the-full-experience-on-linux}

フローティングボールを含む完全な UX を使うには、**Xorg** セッションを利用してください。GNOME の場合の手順です。

1. ログアウトします。
2. ログイン (GDM) 画面で、ユーザー名をクリックします。
3. 右下の隅にある歯車 (設定) アイコンをクリックします。
4. **GNOME on Xorg** (または「Ubuntu on Xorg」) を選択します。
5. ログインします。

OpenPen は起動時にセッションを自動的に検出するため、設定は不要です。

## これらの制限がある理由

Wayland コンポジターは、クライアントアプリケーションに許可する操作を意図的に制限しており、その多くが透明な最前面オーバーレイに影響します。

- アプリケーションは自身のトップレベルウィンドウの位置を指定できないため、OpenPen はフローティングボールを配置したり、バーをボールに追従させて移動したりできません。
- 透明なウィンドウを確実に完全なクリックスルーにすることはできないため、バーの占有領域は操作可能なままになります。
- グローバルなカーソル位置とグローバルなキーボードショートカット は、X11 のようにはアプリケーションに公開されません。そのため、カーソル基準の操作や汎用的なグローバルショートカット は利用できません (代わりに GNOME 独自のキーバインド機構を使用しています)。

X11/Xorg にはこうした制限がないため、macOS や Windows と同等の体験が得られます。

## 報告

お使いの Linux 環境で OpenPen が上記の説明どおりに動作しない場合は、GitHub の Issue を開き、次の情報を含めてください。

1. `echo "$XDG_SESSION_TYPE"` の出力。
2. デスクトップ環境とそのバージョン (例: GNOME 46)。
3. ディストリビューションとそのバージョン。
4. 実機で実行しているか、仮想マシンで実行しているか。
