# OpenPen UIKit

OpenPen UIKit のラッパーは、inject キー、相互排他、アニメーションガード、マウスパススルーを自動的に処理します。plugin 開発者はまずここから始めてください。基盤となるヘッドレスライブラリの知識は不要です。

インポートパス:

```ts
import {
  AppButton, AppButtonDropdown,
  AppPopover, AppDialog,
  AppSlider, AppToggle, AppSegmented,
  AppSelect, AppTooltip, AppTabs,
  AppBanner,
  useDialog, useDialogPluginComponent,
} from '@openpen/module-api/uikit'
import type { BannerVariant } from '@openpen/module-api/uikit'
```

> 以下に記載のないウィジェット (タグ入力、数値スピナー、コンボボックス) については、[custom-components.md](./custom-components.md) を参照してください。

## 3 つのレイヤー — 用途に合ったレベルを選ぶ

UIKit は 3 段階のエスカレート式 API アクセスを提供します。最初に適切なレベルを選ぶことで、後からの書き直しを防ぐことができます。

| レイヤー | インポートパス | DX コスト | ビジュアルの一貫性 | バンドルへの影響 | 自由度 |
|---|---|---|---|---|---|
| **ラッパー** | `@openpen/module-api/uikit` | 低 | 自動 — トークンが自動適用される | 最小 | 低 |
| **プリミティブ再エクスポート** | `@openpen/module-api/uikit` (名前付きエクスポート) | 中 | トークン駆動 — CSS は自分で記述する | 中 | 高 |
| **カスタムコンポーネント** | `@openpen/module-api/uikit` のプリミティブ + 独自コンポーネント | 高 | トークン駆動 — マークアップと CSS は自分で記述 | 中 | 最高 |

### 判断基準

**ラッパー** — ほとんどのコンポーネントにはこちらを使用してください。ポップオーバー、ダイアログ、スライダー、トグルなどをボイラープレートなしで利用できます。inject キー、相互排他、ControlBar アニメーションガード、マウスパススルーはすべて内部で処理されます。

**プリミティブ再エクスポート** — マークアップとスタイリングを完全に制御しつつ、ヘッドレスプリミティブが提供するアクセシビリティとキーボードナビゲーションの動作 (フォーカストラップ、ARIA 属性、キーボードクローズなど) を維持したい場合に使用してください。CSS は自分で記述し、相互排他とパススルーも自分で管理します (`docs/uikit/primitives.md` を参照)。

**カスタムコンポーネント** — どのラッパーも対応していない UI パターン (タグ入力、数値スピナー、グラフエディタなど) に使用してください。プリミティブの再エクスポートと独自のマークアップを組み合わせ、`--openpen-*` デザイントークンでスタイルを設定すると、ホストのテーマに追従します。ビジュアルの一貫性とそのサーフェスの長期的なメンテナンスは自分で担います。詳しくは [custom-components.md](./custom-components.md) を参照してください。

plugin は自身の `package.json` に `reka-ui` をインストールしたり、直接インポートしたりしてはなりません (MUST NOT)。どのレイヤーでも、ヘッドレスプリミティブは `@openpen/module-api/uikit` から取得します。これにより、ホストが基盤となるヘッドレスライブラリを入れ替えても (後述の「基盤となるヘッドレスライブラリを入れ替える場合」を参照)、plugin は動作し続けます。

> どのレイヤーを使うか迷った場合は、ラッパーから始めてください。後から下のレイヤーに降りることは常にできますが、逆は難しくなります。

## 基盤となるヘッドレスライブラリを入れ替える場合

OpenPen UIKit は現在、ヘッドレス動作レイヤーとして **Reka UI** をラップしています。これは内部の実装詳細です。`@openpen/module-api/uikit` からのみインポートする plugin 開発者には見えないはずです。

Reka UI が非推奨になったり、放棄されたり、プロジェクトのニーズから大きく乖離した場合、ホストには文書化されたフォールバック順序があります:

1. **Headless UI Vue** (Tailwind Labs の公式 Vue ポート) — 成熟しており、広く使われており、コンポーネントセットは小さめです。
2. **Ark UI** (Zag.js ベース、Vue サポートつきのクロスフレームワーク) — より広いコンポーネントカバレッジ、ステートマシン駆動です。
3. **自作ヘッドレスプリミティブ** — 上記のどちらも選択肢にならない場合の最終手段です。

### 各レイヤーへの影響

| レイヤー | ライブラリ入れ替えの影響 |
|---|---|
| **ラッパー** (`@openpen/module-api/uikit`) | コードの変更は不要です。ラッパー API (プロパティ、イベント、スロット) はホストが管理する安定したコントラクトです。 |
| **プリミティブ再エクスポート** (`@openpen/module-api/uikit` の名前付きプリミティブ) | メジャーバージョンのバンプが行われます。変更されたプリミティブコンポーネント名やプロパティを更新するために、小規模で限定的なポートが必要になります。 |
| **カスタムコンポーネント** (プリミティブの再エクスポートで構築した独自コンポーネント) | 組み合わせたプリミティブはプリミティブレイヤーと同じ影響を受けます。独自のマークアップと CSS は影響を受けません。 |

どのレイヤーに投資するかを判断できるよう、この情報を事前に文書化しています。ラッパーレイヤーは、ライブラリの入れ替えをまたいで維持することをホストチームがコミットする長期的なコントラクトです。最大限の UI の自由よりも長期的な安定性を重視する場合は、ラッパーが適切な選択です。
