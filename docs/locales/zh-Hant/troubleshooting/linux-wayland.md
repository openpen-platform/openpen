# Linux 與 Wayland 支援

OpenPen 可在 Linux 上執行，但屬於**有條件支援**，取決於你的顯示工作階段：

- **X11 / Xorg 工作階段** — 完整體驗，與 macOS 和 Windows 相同
  （浮動球、展開／收合、拖曳吸附、釘選、垂直列）。
- **原生 Wayland 工作階段**（GNOME，目標版本 46 以上）— 可正常使用但**功能縮減**的體驗：
  以固定、常駐顯示的控制列取代浮動球。

這是為配合合成器（compositor）限制而做的刻意調整，並非未完成的移植。在 Wayland 上，
OpenPen 的行為較接近務實的螢幕標註工具，而非完整的浮動球 UX。

---

## 我正在執行哪種工作階段？

```bash
echo "$XDG_SESSION_TYPE"   # → "x11" or "wayland"
```

若想取得完整體驗，請登入 **Xorg** 工作階段（參閱下方
[在 Linux 上取得完整體驗](#getting-the-full-experience-on-linux)）。

## 功能支援對照表

| 功能 | X11 / Xorg | 原生 Wayland（GNOME） |
| --- | --- | --- |
| 繪圖覆蓋層（手繪／直線／形狀） | ✅ | ✅ |
| 筆觸粗細、顏色、螢光筆模式 | ✅ | ✅ |
| 浮動球 | ✅ | ❌（改用固定控制列） |
| 拖曳浮動球／吸附邊緣／釘選 | ✅ | ❌ |
| 收合為浮動球／垂直列版面 | ✅ | ❌ |
| 控制列位置 | 跟隨浮動球 | 固定於左上角，常駐顯示 |
| 隱藏控制列（釋放其佔用區域） | ✅ | ✅ — `Ctrl + Shift + \` 或系統匣 |
| 鍵盤快捷鍵 | ✅ | ✅ — 僅限 GNOME |
| 游標相關動作（召喚至游標處） | ✅ | ❌ |
| 多螢幕 | ✅ | ⚠️ 控制列位於作用中的螢幕；無法跨螢幕拖曳 |

## Wayland 限制詳述

在原生 Wayland 工作階段中：

- **沒有浮動球。** 控制列是固定大小的視窗，釘在左上角且常駐顯示。
  你無法拖曳、收合為浮動球、釘選，或切換為垂直版面。
- **控制列會佔用其涵蓋區域。** 由於在 Wayland 上無法讓控制列視窗點擊穿透，
  其涵蓋的區域無法與下層應用程式互動。需要該空間時，請以 **`Ctrl + Shift + \`**（預設）
  或系統匣選單隱藏控制列，並以相同方式重新顯示。
- **快捷鍵僅支援 GNOME。** OpenPen 會將其切換動作（切換繪圖模式、隱藏控制列）
  註冊為 GNOME 自訂按鍵綁定。預設為 `Ctrl + Shift + A`（繪圖模式）與
  `Ctrl + Shift + \`（隱藏控制列）。其他 Wayland 合成器（KDE 等）尚未支援。
- **沒有游標相關功能。** 依賴全域游標位置的動作（例如召喚至游標處）無法使用，
  因為 Wayland 不會向應用程式提供全域指標位置。
- **繪圖畫布為隨需建立。** 繪圖覆蓋層在進入繪圖模式時建立，離開時銷毀。
  已完成的筆觸會保留，但在少數情況下，離開繪圖模式時仍在進行中的筆觸
  （指標尚未放開）可能會遺失。為避免此情況，請先完成筆觸（放開指標），
  再關閉繪圖模式。
- **多螢幕。** 控制列位於作用中的螢幕，無法跨螢幕拖曳。

## 在 Linux 上取得完整體驗 {#getting-the-full-experience-on-linux}

若要取得完整的浮動球 UX，請使用 **Xorg** 工作階段。在 GNOME 上：

1. 登出。
2. 在登入（GDM）畫面點選你的使用者名稱。
3. 點選右下角的齒輪／設定圖示。
4. 選擇 **GNOME on Xorg**（或「Ubuntu on Xorg」）。
5. 登入。

OpenPen 會在啟動時自動偵測工作階段，無需任何設定。

---

## 這些限制的成因

Wayland 合成器刻意限制用戶端應用程式的能力，其中數項限制會影響透明的置頂覆蓋層：

- 應用程式無法自行定位其頂層視窗，因此 OpenPen 無法放置浮動球，
  也無法移動控制列使其跟隨浮動球。
- 透明視窗無法可靠地達成完全點擊穿透，因此控制列涵蓋的區域仍會攔截互動。
- 全域游標位置與全域鍵盤快捷鍵 不像在 X11 上那樣開放給應用程式，
  因此游標相關動作與通用全域快捷鍵 無法使用（改用 GNOME 本身的按鍵綁定機制）。

X11/Xorg 不受這些限制，因此該環境下的體驗與 macOS 和 Windows 一致。

## 回報問題

若 OpenPen 在你的 Linux 環境中的行為與上述不符，請開立 GitHub issue 並附上：

1. `echo "$XDG_SESSION_TYPE"` 的輸出。
2. 你的桌面環境與版本（例如 GNOME 46）。
3. 你的發行版與版本。
4. 你是在實體硬體還是虛擬機器上執行。
